## L4 monthly refresh
| File | What it does |
|---|---|
| `flows/refresh_flow.py` | NEW. One month per run: probe the TLC files after the newest processed month (403/404 = not published yet), download, extend the weather file, clean all months, score the champion on the new month, re-materialize Feast, train a geo+L1 challenger validated on the new month, report whether it WOULD be promoted (never promotes), then `finish_month` (DVC, then state). `--dry-run`, `--serve` (cron 07:00). Report: `data/processed/refresh_<month>.json`. |
| `src/validation/clean.py` | **MODIFIED.** The CLI now defaults to every `yellow_tripdata_*.parquet` in `--raw-dir` (was a fixed Jan-Mar list), so `dvc repro` after a refresh keeps the new month instead of overwriting `trips_clean.parquet` without it. New `discover_months`. |
| `tests/test_refresh_flow.py` | NEW. 33 tests, no network (file:// URLs, injected probes/MLflow/DVC). |

Design notes: the new month is the validation month (same rule as `retrain_flow`), so the challenger never trains on the
newest month. An empty state file means the original Jan-Mar months. Rerunning after a failure repeats the month and may
register one extra challenger version.
